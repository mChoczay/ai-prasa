# Glossary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add plain-language explainers for hard terms. One Haiku call per edition picks the terms and writes the explanations; they are kept in an n8n table, published as `glossary.json`, and shown as "Pojęcia" chips that open a card.

**Architecture:**
- `n8n/lib/glossary.js` builds the prompt and merges Haiku's answer with the known terms.
- `PPAI · profiles` gets five nodes between `Finish edition` and `Relay?`: read, prompt, Haiku via `PPAI · claude`, merge, save.
- `publishTree` writes `glossary.json`.
- The site loads it and renders the chips and the card.

**Tech Stack:** vanilla ES modules, n8n Code / Data table / Execute Workflow nodes, `node --test`.

**Spec:** `docs/specs/2026-11-20-glossary-design.md`

## Global Constraints

- Project rules as in earlier plans:
  - no dependencies;
  - owner commits ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - no host or keys in the repo;
  - each stage ≤ 180 s;
  - no `URL` in Code nodes.
- Tests run with `.tools/node/node.exe --test`.
- Limits:
  - ≤ 3 terms per story and ≤ 12 per edition;
  - `explain` ≤ 600 characters;
  - `term_id = entityId(term)`.
- Haiku call:
  - `step: 'glossary'`, `model: 'claude-haiku-5-5'`, `effort: 'low'`, `max_tokens: 2500`;
  - system prompt `prompts/glossary.md`;
  - schema `schemas/glossary.schema.json`: `{ stories: [{ idx: integer, terms: [{ term: string, explain: string }] }] }`.
  - A known term comes back with `explain: ''`.
- Copy:
  - the story line reads `Pojęcia: ` followed by the chips;
  - a chip is `<button class="term" data-term="ID">TERM</button>`;
  - the card is `<div class="term-card"><h3>TERM</h3><p>EXPLAIN</p></div>`.
- Failure handling: if the Haiku call or the merge fails, the edition goes on without `terms` and the known glossary is still published.

## Review Focus

1. Haiku returns a term already known under a different case or spacing ("h200" vs "H200"). It must map to the existing id, with no duplicate row. Test in Task 1.
2. Haiku returns more than 3 terms for a story, an `idx` out of range, an empty `term`, or a new term with an empty `explain`. Extra or invalid entries are dropped. Test in Task 1.
3. The claude sub-workflow fails (`ok: false`) or the node errors. The edition still continues to publish, without `terms`. Test in Task 2.
4. An old edition, or a story without `terms`, or a term id missing from `glossary.json`: no "Pojęcia" line, and no broken chip. Test in Task 3.
5. Term text containing HTML or quotes is escaped in chips and cards. Test in Task 3.

### Task 1: Glossary library, prompt and schema

**Files:**
- Create: `n8n/lib/glossary.js`, `prompts/glossary.md`, `schemas/glossary.schema.json`, `tests/glossary.test.js`
- Modify: `tests/schemas.test.js` if it enumerates schema files

**Interfaces:**
- Produces:
  - `glossaryPrompt(edition, knownTerms, feedback = '') -> string`. It lists the stories as `[idx] title — lede — first 600 characters of body`, then the known terms by name, then `## Reader feedback\n…` when feedback is set.
  - `mergeGlossary(edition, answer, knownRows, date) -> { edition, newRows, glossaryJson }`:
    - `knownRows` is `[{ term_id, term, explain, first_date }]`;
    - `answer` is the Haiku `data`, possibly invalid;
    - the result `edition` is a copy whose stories carry `terms: [ids]` (only ids with an entry after the merge);
    - `newRows` are rows to insert;
    - `glossaryJson` is `{ terms: [{ id, term, explain }] }` for all known and new terms, sorted by `term`.
  - Stories are indexed like `_storySlots` in `profiles.js`: lead story first, then `stories` in order.

- [ ] **Step 1: Failing tests.**
  - The prompt contains each story title with its idx and the known term names.
  - The `## Reader feedback` section appears only when feedback is non-empty.
  - Merge with answer `{ stories: [{ idx: 0, terms: [{ term: 'H200', explain: 'Układ…' }, { term: 'eksport chipów', explain: 'Zasady…' }] }, { idx: 1, terms: [{ term: 'h200', explain: '' }] }] }` and no known rows:
    - two `newRows`, with ids `h200` and `eksport-chipow`;
    - story 0 gets `['h200', 'eksport-chipow']` and story 1 gets `['h200']`;
    - `glossaryJson` has 2 terms.
  - With a known row `h200`, an answer of `H200` and an empty explain: no new row, and the story gets `['h200']`.
  - Dropped entries:
    - a fourth term on a story;
    - `idx: 99`;
    - an empty `term`;
    - a new term with an empty explain.
  - An `explain` over 600 characters is cut to 600.
  - More than 12 terms per edition are cut.
  - `answer = null` or `{}` gives an edition without `terms` and `newRows = []`; `glossaryJson` still has the known terms.

    - "skip obvious AI words and company or model names";
    - "explain in 3–4 plain sentences what it is and why it matters for this story";
    - "for a known term return it with an empty explain".

- Test: `tests/workflow-profiles.test.js`, `tests/publish.test.js`, `tests/stages.test.js`

**Interfaces:**
- Consumes: `glossaryPrompt` and `mergeGlossary` (Task 1).
- Produces these nodes, in order after `Finish edition`:
  - data table get `Read glossary` (table `glossary_terms`, returnAll, alwaysOutputData, onError continue);
  - Code `Glossary prompt` returning `{ user }`;
  - Execute Workflow `Glossary with Haiku` (`PPAI · claude`, mode once, onError continue);
  - Code `Glossary done`. It reads `$('Finish edition').first().json` and replaces `edition`. It adds `glossary_json` and `glossary_rows`, wrapped in try/catch so the edition passes through unchanged on error.
  - If `Any new term?` → data table insert `Save glossary` (rows from `glossary_rows`). The insert must not block the relay.
  - `Relay?` now follows `Glossary done`. `Spotlight items` and `Mark spotlight` stay on `Finish edition`.
- The payload to publish carries `glossary_json`.

  - `Glossary done` with a valid claude result: the edition stories have `terms`, and `glossary_json.terms` is non-empty.
  - With `{ ok: false }`, or no node data: the edition equals the `Finish edition` edition, `glossary_json` holds the known terms, and `glossary_rows` is empty.
  - `publishTree` with `glossaryJson` adds the path `site/data/glossary.json`; without it, it doesn't.
